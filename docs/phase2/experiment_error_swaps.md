# Phase 2 实验记录：SFT 与 GRPO 错题互换分析

## 实验背景

本记录用于分析 `SFT` 与 `GRPO` 在正式 `official` 评测口径下的错题互换现象。

- 评测入口：`scripts/eval_dataset.py`
- 评测模式：`official`
- 数据集：`data/eval/gsm8k_dev200.jsonl`
- 对比模型：
  - `outputs/sft-qwen3-1.7b`
  - `outputs/grpo-qwen3-1.7b`

逐题对比结果：

- `both_correct = 150`
- `both_wrong = 36`
- `sft_only = 6`
- `grpo_only = 8`

结论上，这次 `SFT` 与 `GRPO` 都答对了 `157/200`，因此 `normalized_accuracy` 同为 `0.785`，但并不是完全相同的 157 道题。

## SFT错 -> GRPO对

这一组样本的主要特征是：`GRPO` 修正了部分题意理解、单位处理、符号方向和简单约束建模错误。

代表样例：

- `id=380`：利息题。`SFT` 把 `10%` 和 `5 months` 机械相乘导致过高估计，`GRPO` 改成更接近题意的总利息计算，答案从 `1095` 修正到 `803`。
- `id=1187`：雪雪球题。`SFT` 实际已推到正确时间，但 boxed 收尾被截断；`GRPO` 生成了完整的 `Final answer`，从 parse fail 变为正确。
- `id=1265`：柠檬汁题。`SFT` 把“额外一加仑更酸”错误扩张为 `8 cups`，`GRPO` 正确理解为额外一加仑用 `2 cups`，答案从 `72` 修正到 `36`。
- `id=653`：工资扣款题。`SFT` 给出 `-80`，`GRPO` 修正了符号方向，输出 `80`。
- `id=606`：轮胎转数题。`SFT` 把单个轮胎的可承受转数错误扩到四个轮胎，`GRPO` 修正为按单个轮胎计算，答案从 `24` 修正到 `6`。
- `id=635`：空手道课程题。`SFT` 没有把“缺课会提高每节平均成本”建模进去，`GRPO` 列出 `60 / (10 - x) <= 10`，得到 `4`。
- `id=936`：酒店住宿题。`SFT` 把 `5 pm -> 次日 10 am` 错看成只多 3 小时，`GRPO` 正确算成总共 17 小时，答案从 `390` 修正到 `250`。
- `id=1076`：餐饮收入题。两边本质都算对，`GRPO` 输出 `162.00`，在 `math-verify` 下可正确对齐到标准答案。

## SFT对 -> GRPO错

这一组样本的主要特征是：`GRPO` 更容易把原本简洁正确的解法拉成长推理，并在中间步骤丢失题意约束、重复累计或引入额外假设。

代表样例：

- `id=1119`：家务时间题。`SFT` 用最小必要假设给出 `18`，`GRPO` 把 Dior 的时长扩成 `14`，答案漂到 `24`，并在结尾重复多次 `Final answer`。
- `id=25`：购物题。`GRPO` 把已知花费算成 `21` 而不是 `33`，后续又做了“向下取整 3 盒”的伪验证，答案从 `2` 漂到 `3`。
- `id=210`：存钱买衣服题。`GRPO` 把 babysit 和 mow 拆成两个独立凑满目标的过程，丢掉了“已有存款 + babysit 收入 + mow 收入共同构成总额”的约束，答案从 `10` 漂到 `15`。
- `id=996`：儿童年龄题。`GRPO` 推理到最后一步时截断，没有给出完整 boxed 收尾；这是这一组里唯一明显的格式/解析退化样例。
- `id=927`：糕点热量题。`GRPO` 先把总数合成 `500`，再分别乘 `200` 和 `150` 后相加，出现重复累计，答案从 `85000` 漂到 `175000`。
- `id=943`：CD 折扣题。题里 “sells them for 40” 表示 5 张一共卖 `40`，`GRPO` 错当成每张 `40`，算成 `110`。

## 当前结论

这次对比说明，当前 `GRPO` 带来的不是单向稳定增益，而是一次明显的解题风格重排：

- 好处是：它修正了部分题意理解、单位/符号方向和简单约束建模错误。
- 风险是：它也更容易把本来不需要复杂推理的简单题过度展开，并在中途丢掉关键约束。

因此，当前 Phase 2 的主要问题不再是 boxed 协议或答案解析，而是：

- `GRPO` 对哪些题型有真实增益
- `GRPO` 是否会系统性伤害简单算术建模题
- 当前 reward 与数据筛选是否把模型推向了“更会展开推理，但不一定更稳”的解题风格
